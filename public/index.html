Frequently Asked Questions

Everything you need to know about the Code Clinic diagnostic methodology.

How does Dr. Debug differ from general search engines or code generators?

Code Clinic operates as a senior pair-debugging physician. Instead of dumping walls of generic code or dozens of search links, it asks focused questions to narrow down the symptom, explains the precise root cause ("why this happens"), and prescribes the smallest surgical patch first.

When does Dr. Debug perform web searches?

Dr. Debug preserves speed and token budget by not searching on timeless bugs (syntax errors, off-by-one errors, null checks). It specifically triggers web searches when encountering recent library versions (e.g. Next.js 15, React 19), obscure error strings, or breaking API changes.

How does the "Learning while typing" loop work without fine-tuning?

Fine-tuning LLM weights live is slow and unreliable. Code Clinic uses RAG (Retrieval-Augmented Generation) memory. Each solved case and outcome feedback ("Did this solve it?") is stored with error signatures, stack metadata, and tested patches. Future queries match these signatures and boost verified cures.

Is code executed safely?

Yes. Code testing in the ICU Sandbox runs inside bounded child processes with strict timeouts, standard isolation, and no elevated permissions.
